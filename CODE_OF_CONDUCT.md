# Code of Conduct

Mapping Voices exists to make real oral-history and voice-testimony
collections easier to find. It's meant to be a place archives, researchers,
students, and institutions can contribute to without friction — this
document is about keeping it that way.

## The short version

Be respectful, be honest, and act in good faith. Disagreements about a
collection's description, categorization, or inclusion are normal and
welcome; treat them as a content question, not a personal one.

## Expected behavior

- Engage constructively in issues, pull requests, and discussions.
- Assume good faith — most disagreements here are about how to accurately
  describe a real collection, not about anything personal.
- Respect that contributors range from professional archivists to students
  to interested members of the public. No contribution is too small, and no
  question is "too basic" to ask.
- Hold the project's data-honesty rule (see `CONTRIBUTING.md` and
  `SPEC.md`) as a shared value: every entry should describe something real.
  Calling out an inaccurate or unverifiable entry is a contribution, not an
  attack on whoever added it.

## Unacceptable behavior

- Harassment, personal attacks, or discriminatory language or jokes,
  in any project space (issues, pull requests, discussions, commit
  messages, code review).
- Deliberately submitting fabricated, misleading, or unverifiable entries
  after being asked to substantiate them.
- Publishing others' private information without consent.
- Any conduct that would be inappropriate in a professional academic or
  cultural-heritage setting.

## Scope

This applies within all project spaces on GitHub (issues, pull requests,
discussions, code review) and in any other context where someone is acting
as a representative of the project.

## Reporting

If something happens that isn't addressed by normal moderation (closing a
low-effort issue, requesting changes on a PR), open a GitHub issue if you're
comfortable doing so publicly, or reach out directly to the maintainer
listed in the repository — see the contact details on the project's GitHub
profile. Reports will be handled as discreetly as the situation allows.
